나라장터 D1 카테고리·업로드일자 관리 V26
==========================================

1. 배포
 - 기존 GitHub kcbdc/g2b 저장소의 worker.js를 이 패키지의 worker.js로 교체합니다.
 - 기존 wrangler.jsonc의 main = "./worker.js"를 유지합니다.
 - 별도 index.html을 GitHub 정적 Assets로 배포하지 마세요. Worker가 화면과 API를 함께 제공합니다.
 - Cloudflare D1 바인딩 DB, Secret G2B_API_KEY, Secret UPLOAD_KEY를 유지합니다.
 - 배포 후 /api/health에서 version=V26, dbConfigured=true 확인.
 - D1 스키마는 최초 관리자 인증 요청에서 자동 생성됩니다.
 - 사전 DB 백업을 권장합니다. DB 기존 companies/upload_log 테이블은 삭제하지 않습니다.

2. 카테고리별 업로드
 - 관리 비밀번호 입력 → 연결하고 명단 불러오기.
 - 업로드 카테고리 중 물품/일반용역 / 공사 / 용역 선택.
 - 엑셀 파일 선택, 시트 선택, 미리보기 확인.
 - ‘이 명단으로 교체’는 해당 카테고리의 이전 활성 업로드를 비활성화하고 새 파일을 활성화합니다.
 - ‘기존 명단에 추가’는 해당 카테고리의 활성 파일을 유지하면서 새 파일을 추가합니다.
 - 과거 업로드는 삭제되지 않고 업로드 파일 목록에서 재선택 가능합니다.

3. 조회 명단 불러오기
 - 카테고리, 업로드 날짜, 업로드 파일을 선택하고 ‘선택 명단 불러오기’를 누릅니다.
 - 파일=현재 활성 명단, 날짜=전체이면 선택한 카테고리의 현재 사용 중인 명단을 조회합니다.
 - 파일을 특정 업로드 ID로 선택하면 이전 비활성 파일도 조회할 수 있습니다.
 - 날짜를 특정 날짜로 선택하면 그 날짜의 이전 업로드 기록도 포함됩니다.
 - 동일 사업자번호가 여러 파일에 있으면 화면에서는 해당 필터 내 가장 최근 업로드값 한 건으로 표시합니다.
 - 조회 허용 목록도 선택한 범위로 검증합니다.

4. CSV 및 복구
 - 다운로드 CSV에는 사업자번호, 업체명, 카테고리, 업로드일자, 개업일, 여성·장애인·사회적기업, 중소기업, 상태가 포함됩니다.
 - CP949 인코딩 CSV를 유지합니다.
 - 기존 브라우저 결과는 사업자번호 기준으로 유지하며 다른 카테고리·명단으로 전환하면 통계만 재계산합니다.
 - HTTP 429이면 중단하며 이후 '미완료 업체 조회'를 사용합니다.

5. V25 기존 업체 이관
 - 기존 companies 테이블에 남아 있는 업체는 최초 실행 시 '미분류 / V25 기존명단'으로 자동 이관됩니다.
 - 이관 후 새 업로드는 세 가지 지정 카테고리 중 하나를 선택해야 합니다.
 - D1 데이터베이스를 실제로 수정하는 것은 새 Worker의 운영환경 실행 시점이며, 이 ZIP 다운로드만으로는 운영 DB가 변경되지 않습니다.

6. 보안
 - UPLOAD_KEY 및 G2B_API_KEY 값은 소스에 적지 마세요.
 - 운영용 공개 Worker는 Cloudflare Access 등으로 접근을 제한하세요.
 - 결과 기록과 D1 업로드 파일에는 사업자번호·업체명이 포함되므로 접근 권한 관리가 필요합니다.

테스트: node --check(Worker/UI), 모의 D1 카테고리별 교체/추가/이력 조회/조회 허용 테스트 완료.
실제 Cloudflare Production D1 배포 및 외부 API 실조회는 여기서 실행하지 않았습니다.
